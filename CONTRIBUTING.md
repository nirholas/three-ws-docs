# Contributing

Thank you for helping make three.ws easier to use. This repository is documentation only, so contributing means writing, correcting and testing instructions.

## Ways to help

- Fix a wrong step, a dead link or an out-of-date number
- Add a troubleshooting entry for something that tripped you up
- Write a tutorial that ends with something working
- Improve a snippet, and prove it runs

## Ground rules

1. **Verified, not guessed.** Every command, URL, version and claim must be something you ran or read from the live platform. If you are not sure, say so in the pull request.
2. **No secrets, ever.** No tokens, keys, seed phrases or private data in text, screenshots or snippets.
3. **No application code.** Snippets are small examples. Product code belongs in [nirholas/three.ws](https://github.com/nirholas/three.ws).
4. **Plain, direct writing.** Short sentences. Say what to do and what you should see. Skip filler and hype.
5. **No other-project promotion.** three.ws promotes `$THREE` only. Do not add links or recommendations for other tokens or projects.
6. **Screenshots** follow [assets/README.md](assets/README.md): signed out or from a throwaway account.
7. **Punctuation.** Use periods, commas, colons and parentheses. Do not use the em-dash character.

## Style

- Title each page with what it helps the reader do.
- Lead with the outcome ("You will end with...") on tutorials.
- Show commands in fenced blocks with a language tag. Use `text` for prompts.
- Link to the live source of truth rather than copying values that change.
- Relative links between pages in this repo.

## Submitting

1. Fork and branch.
2. Make your change. Run any snippet you touched.
3. Add a line to [CHANGELOG.md](CHANGELOG.md) under Unreleased.
4. Open a pull request and fill in the template.

## Product bugs

If the app or platform is broken, file it on [nirholas/three.ws](https://github.com/nirholas/three.ws/issues).
